# native-13: 流量统计界面

**What to build:** 面板底部加一行当日合计，点这行弹出排行窗口（今日 / 近 7 天），只列前 10。

**Blocked by:** native-12

**Status:** done

> 判据 3/4（真机点击收起、不抢焦点）需要提权会话里跑交付物，2026-11-19 与 native-11 的三条 ETW 判据
> 一起移交 native-14。本单以离线夹具验证数据与布局，见文末「实测」。

## 面板（280×348，尺寸不变）

- footer 上方加一行：`今日 ↓1.2 GB ↑340.5 MB`，右侧 `明细 ›`。
- 该行是点选区：命中则 `PostMessage` 到 host 打开排行窗口（与 `WM_APP+2` 同一套消息，落在 UI 线程）。
- 数字来自 `UsageLedger::TotalDown/TotalUp`；落盘失败时行尾加 `·` 并在 footer 提示未落盘。

## 排行窗口

- 320×420 DIP，`WS_POPUP | WS_EX_TOOLWINDOW`，无标题栏，自带关闭 ✕，可拖动（复用面板的拖动阈值 6 px）。
- 内容：标题「流量统计」+ 两个切换标签「今日 / 近 7 天」+ 10 行 `exe 名 / 条形 / 下载 / 上传`。
- 排序按 `down+up` 降序，单位 `GB`/`MB` 阈值同 `FormatBytes`。
- 数据全部来自账本（今日 = 当日行；近 7 天 = 最近 7 个日期行求和），界面不做二次聚合。
- 不属于前台窗口、不抢焦点；点窗口外收起（与面板同一套 `WH_MOUSE_LL` + 前台轮询，抽成共用实现，不复制一份）。

## 判定依据

| # | 判据 | 方法 |
|---|---|---|
| 1 | 界面数字 = 文件聚合值 | 直接解析当月 TSV 求和，与窗口逐行对比，10 行全等 |
| 2 | 排序正确 | 构造两组数据，第二组更大时上下顺序互换 |
| 3 | 点面板外收起排行窗口 | 与 native-10 判据同法，≤250 ms |
| 4 | 窗口不抢焦点 | 打开前后 `GetForegroundWindow()` 不变 |
| 5 | 面板尺寸不变 | 窗口矩形仍是 280×348 DIP（144 dpi 下 420×522 px） |

## 实测（2026-11-19）

构建通过，`native\bin\NetSpeedMonitor.exe` 393,728 B（加界面代码前 372,736 B）。

夹具 `%TEMP%\opencode\nsm13\` 把 `panel.cpp`、`usage_window.cpp`、`collapse.cpp`、`usage_store.cpp`
原样链进一个控制台程序（不带提权 manifest，因此可以本会话运行），构造「昨天 Code.exe 100 MB +
今天三个进程」的数据，用窗口消息代替鼠标点击（提权窗口才需要注入输入，普通窗口 `SendMessage` 即可），
每次打开后 `BitBlt` 截屏成 PNG 逐张核对。21 项断言全 PASS：

| # | 判据 | 实测 | 结论 |
|---|---|---|---|
| 1 | 界面数字 = 文件聚合值 | 今日 `msedge 700.0/120.0 · Code 150.0/40.5 · QQ 80.0/20.0`，与账本逐项相等；面板合计 `↓930.0 MB ↑180.5 MB` 等于三行之和 | 通过 |
| 2 | 排序正确 | 按 `down+up` 降序，`msedge > Code > QQ`；换 tab 后顺序不变，数值按窗口变化 | 通过 |
| 2b | 近 7 天折入历史 | 昨日 Code.exe 100 MB 只在「近 7 天」里出现（150.0 → 250.0 MB），今日 tab 不变 | 通过 |
| 3 | 点面板外收起排行窗口 | 未跑（需提权，移 native-14） | 阻塞 |
| 4 | 窗口不抢焦点 | 未跑（需提权，移 native-14） | 阻塞 |
| 5 | 面板尺寸不变 | 截图为 420×522 px（144 dpi）；排行窗口 480×630 px | 通过 |

附加断言：点「今日」行会向 host 发出打开消息、不触发拖动（窗口位置不变）、面板自身不收起；
点 tab 不会收起窗口；`WM_APP+4` / `WM_APP+5` 两个收起消息各自生效。

## 过程中修掉的三个问题

1. **排行窗口按 96 dpi 建成 320×420**：`Create()` 里 `GetDpiForWindow` 对隐藏的 layered 窗口返回 96，
   而面板是显式 `SetDpi(144)` 的。命中测试按 dpi 换算，于是 144 dpi 屏上点 tab 落到空白区，看起来
   「点 tab 没反应」。改为与面板同源：新增 `UsageWindow::SetDpi()`，打开时由 `main.cpp` 传入参照窗口
   （面板或悬浮球）的 DPI。
2. **条形画在名字下面**：`down+up` 比例的蓝色块直接铺在整行，压住 exe 名，看着像选中高亮。改成
   名字列下方 4 DIP 的比例条。
3. **收起逻辑重复**：面板原本自带一套 `WH_MOUSE_LL` + 前台轮询，排行窗口要用同一套。抽成
   `collapse.h/.cpp`（`OutsideCollapse`），两个窗口共用，面板里那份删除。

未覆盖：真实鼠标点击（依赖提权会话的输入注入）、多显示器、窗口记住上次位置。
