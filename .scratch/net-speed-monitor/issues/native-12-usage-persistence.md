# native-12: 流量累计持久化（按天）

**What to build:** 把 native-11 的内存账本按天落到磁盘，启动时读回当日与近 7 天，跨天自动换行，90 天后滚动删除。

**Blocked by:** native-11

**Status:** done

## 文件格式

`%LOCALAPPDATA%\NetSpeedMonitor\usage\YYYY-MM.tsv`，按月一个文件、UTF-8、Tab 分隔：

```
date	exe	downBytes	upBytes	lastSeenUnix
2026-11-19	msedge.exe	123456789	9876543	1763550000
```

- 只追加当日行、重写时整文件原子替换（临时文件 + `MoveFileExW(MOVEFILE_REPLACE_EXISTING)`）。
- 写盘节流：内存累加，距上次落盘 ≥30 s 或增量 >1 MB 才写；退出（`WM_DESTROY`）强制 flush。
- 崩溃最多丢 30 s，不做 WAL。

## 需要处理的边界

- 跨 00:00：新日期开新行，旧行数值冻结。
- 时钟回拨：日期倒退时不删已有行，只累加到较早那天；同一 `date+exe` 行唯一。
- 文件损坏/截断：跳过无法解析的行并继续加载，不崩溃、不写负数。
- 加载失败（权限、磁盘满）：内存账本照常工作，UI 标注「未落盘」。
- 90 天滚动：删除早于 90 天的行，空月份文件直接删。
- 进程名含 Tab 或换行：写入前替换为空格（exe 名理论上不含，防御性处理）。

## 判定依据

| # | 判据 | 方法 |
|---|---|---|
| 1 | 重启后当日值不减 | 记录前值 → 结束进程 → 重启 → 读回值 ≥ 前值 |
| 2 | 跨天换行 | 伪造系统日期或用测试注入当前日期，出现新行且旧行不变 |
| 3 | 损坏容错 | 截断文件末尾 20 字节，加载后不崩溃、无负数 |
| 4 | 原子写 | 写盘过程中断电模拟（强杀进程）后文件仍可解析 |
| 5 | 滚动 | 注入 91 天前的行，加载后被删除 |

## 实测（2026-11-19）

构建通过，`native\bin\NetSpeedMonitor.exe` 372,736 B。

`%TEMP%\opencode\nsm11\` 的 harness 直接调用 `UsageStore` / `UsageLedger`，日期由参数注入（不读系统时钟），
数据目录 `%TEMP%\opencode\nsm12\data\`，每轮先清空。19 项断言全 PASS：

| # | 判据 | 实测 | 结论 |
|---|---|---|---|
| 1 | 重启后当日值不减 | 同一目录二次 `Open`+`SeedToday`，down/up 与落盘前完全相等 | 通过 |
| 2 | 跨天换行 | 11-19 与 11-20 各 1 行，旧行数值不变 | 通过 |
| 3 | 损坏容错 | 文件末尾截断 40 字节后 `Open` 不崩溃、无负数 | 通过 |
| 4 | 原子写 | 保存后目录内无 `*.tmp` | 通过 |
| 5 | 90 天滚动 | 写入 `2026-07.tsv` 后在 11-19 启动时被删除 | 通过 |
| 6 | 聚合窗口 | `Aggregate(7)` = 昨日 + 今日；`Aggregate(1)` = 仅今日 | 通过 |

另外验证：空目录首次运行不报错；空账本保存成功；exe 名与路径分列落盘。

## 过程中修掉的两个 bug

1. **读写字段顺序不一致**：`WriteMonth` 写 `date,name,key`，`LoadMonth` 读 `date,key,name`，重载后 key 与 name
   互换，同一进程被拆成两个账号（当日累计翻倍、Top 榜出现两行同名）。修读取端对齐表头 `date exe path`。
2. **保存后内存副本重复**：写完把整个 `out` 追加进 `rows_`，而 `out` 已包含本月旧行，导致昨日数据在内存里
   出现两次，`Aggregate(7)` 把昨日算了两遍。改为按整月替换（先剔本月、再插入 `out`）。

两个 bug 都只在「保存 → 重新加载 → 再保存」的序列里出现，单次运行看不出，靠 harness 的二次加载断言抓到。

未覆盖：真实系统时钟跨 00:00（用参数注入日期代替）、磁盘写满时的降级表现（只保证不崩溃、保留旧文件）。
